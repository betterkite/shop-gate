# Shop Gate 零售经营看板能力

本 Skill 把已经验证的商品、行为、库存、利润和用户数据，转换成可运行、可解释、可交互的零售经营 BI 工作台。它不是写分析说明的能力；触发后必须产出或更新页面文件，并让页面绑定权威数据。

## 资源

- 只读取与权威 `templateId` 匹配的[零售看板模板](references/scenario_templates.md)。
- 画图前读取[经营指标判读清单](references/visual_judgement.md)。
- 校验最终数据结构、实体覆盖和 mock/远程资源风险时读取[看板数据契约](references/dashboard-data-contract.md)。
- 提交前运行 `python scripts/validate_dashboard_contract.py --input data_file/final/dashboard-data.json`。

## 必须遵守

1. 页面必须绑定 `data_file/final/dashboard-data.json` 或同源数据接口，不能把结论硬编码在页面里。
2. 生成前先确认时间窗口、商品/类目/渠道维度、指标口径和可用图表；不可把比例、库存天数或利润率当成可直接相加的数量。
3. 首屏应快速展示经营结论、关键指标、时间窗口和一张主图或明细表；不要用营销页式大标题或装饰卡片占满首屏。
4. 至少提供一种可核对的数值表格或明细入口；图表、表格和摘要必须使用同一窗口、同一筛选范围。
5. 页面必须包含加载、空数据、失败、刷新和数据限制状态。缺数据时说明缺什么和下一步动作，不用示例数据填补。
6. 用户可见文案优先使用完整中文，例如“页面浏览量（PV）”“独立访客数（UV）”“成交总额（GMV）”“购买转化率”；同时说明统计窗口和计算方式。
7. 商品、类目、渠道、活动和用户列表默认分页；需要查看全部时提供“查看全部”、筛选和页码，不只截取前几条。
8. 筛选、卡片、图表和明细链接要传递 `dataset_id`、时间窗口、维度和值，避免跳回默认数据集或全店范围。
9. 移动端 375/390px 不得出现页面级横向滚动；宽表格只允许在自己的数据区滚动。
10. 不引用外部 CDN、远程脚本、远程样式、远程图片、远程字体或浏览器直连外部接口。
11. 不写入 token、API key、Cookie、Authorization 或其他密钥；来源和质量放在后台 evidence，页面只显示用户需要的更新时间、样本范围和限制。
12. `.data-agent/**` 是平台只读产物。不得编辑、删除、伪造计划、状态、事件、验证报告或视觉截图。

## 页面结构

优先采用连续的经营画布：摘要条 → KPI 指标 → 日趋势 → 维度拆解 → 商品/类目明细 → 库存与转化诊断 → 行动建议 → 数据质量说明。只有确实需要边界时才使用卡片，避免卡片套卡片。

按场景选择模板：

- `funnel-analysis`：浏览、收藏、加购到购买的转化过程。
- `catalog-structure`：商品或类目结构、排名和集中度。
- `price-inventory`：价格、库存、库销比和补货参考。
- `analytics-bi`：总览、趋势、生命周期、留存、利润、库存和价格观察的综合工作台。
- `daily-brief`：经营日报、环比变化和需要关注的维度。

模板只由只读 run plan 的 `visualization.templateId` 和 `variantId` 决定，不因页面实现方便而改成通用页面。

## 标准流程

1. 读取只读 run plan、最终数据和 evidence，确认 `dataset_id`、时间窗口、维度、指标和模板。
2. 按判读清单选择主图、对比图、表格和空态；先处理数据边界，再写页面。
3. 在现有生成工作空间中更新 `app/page.tsx`、必要时更新 `app/globals.css` 或同源 API route。
4. 用 `JsonRecord`、`asRecord()`、`asArray()`、`numeric()` 等守卫处理动态 JSON；不要直接渲染 `unknown`。
5. 验证页面拥有真实数据绑定、图表/表格、过滤和分页状态；只读问答不应因为加载结果而强行生成看板。
6. 交付前运行看板契约脚本和项目规定的构建、类型、Lint、后端、E2E 与桌面/移动视觉门禁。

## 数据和文案边界

- 页面浏览量是行为事件数量，独立访客数按用户去重；购买转化率明确分母。
- 成交总额使用数据中真实价格与购买数量；没有价格时显示缺口，不使用让用户无法理解的“合成价格”表述。
- 库存关注是规则筛选结果，库存天数、销量、浏览量和购买转化应分别说明，不能把提醒直接写成补货结论。
- 没有真实实验分组时，只能展示观察关系或实验模拟参考，并显式说明不能据此得出因果结论。
- 任何日期趋势都要保留日期、指标名称、数值和当前筛选上下文。

## 自动修复边界

看到平台验证失败时，只读取失败 ID 指向的报告和允许修改的页面/数据/evidence 文件，针对失败实际修改；不得修改平台只读产物，不得安装浏览器或用伪造状态绕过验证。修复后交由平台重新构建和验证。
