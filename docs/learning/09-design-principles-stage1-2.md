# 09. 设计思路与架构总账（阶段 1–3 学习笔记）

> 来源：陪学阶段 1（生成-验证-修复-评测闭环）、阶段 2（内核与治理）与阶段 3（Skills 与 Domain Pack）的全部现场笔记。
> 用途：毕业设计《我的类 Shop Gate Agent 项目设计》的骨架。每个原则都标注了项目现场与出处，可直接引用。

---

## 一、一段话总纲

**模型负责聪明，代码负责靠谱。** 整座架构只回答一个问题：如何让 AI 的产出**可信、可停、可修、可考**。可信靠数据管道与验证分层，可停靠状态机与原子暂停，可修靠有界修复与诚实失败，可考靠防作弊的评测与可复现性。

## 二、全景架构：三层

```
┌─ 知识层（阶段 3）─────────────────────────────────────┐
│  .pi/skills 12 份手册 → 编译安检（lock/SHA-256）→      │
│  按阶段/能力目录规则路由注入（零向量）                   │
└──────────────────────┬───────────────────────────────┘
                        │ 手册管判断，代码管执行
┌─ 治理层（阶段 2）─────▼───────────────────────────────┐
│  审批闸门   心跳/租约   fencing 门禁卡   事务 outbox     │
│  replan-only checkpoint            显式降级模式          │
└──────────────────────┬───────────────────────────────┘
                       │ 治理约束施加于每一次执行
┌─ 生成闭环（阶段 1）───▼───────────────────────────────┐
│ 提问 → 查询改写+实体解析 → 任务合同 → 数据预取          │
│      → Agent 执行 → 三类验证 → 受限修复(≤3)            │
│      → 交付 / 拒收(未投影)                             │
└───────────────────────────────────────────────────────┘
```

读取顺序：用户问题先经**确定性安全检查**再到 LLM 做语义增强；数据需求白名单在**任务合同**里冻结；数据由平台预取好才轮到 Agent 上场；产出要过**验证三关**；修不动就拒收。治理层的每件装备横切在闭环的各个节点上；知识层决定"每次执行带着哪几页手册上岗"。

## 三、设计思路十一条

### 原则 1：长任务必须状态机化，状态必须落盘

- **一句原则**：凡是跨时间的任务，先画状态机——状态集合、合法转换、暂停分支、终态语义，一个都不能含糊。
- **现场证据**：十步状态机（`generation-state.ts:6-16`）＋八种运行状态；`needs_clarification` 是粘性的（`:195`，后续更新推不动它）；快照（`generation-state.json`）与流水（`events.jsonl`）双账本并存；四次生成横跨多次进程重启，全靠落盘复活。
- **专业坐标**：durable execution；快照 vs append-only journal 的双账本模式。
- **带走的话**：进程是临时的，账本是永久的。宿主可以死、可以换，状态不能跟着陪葬。

### 原则 2：数据由管道进，不由模型自由发挥

- **一句原则**：模型上岗前，数据已经抓好、洗净、贴好出处——它想编数字都没有素材。
- **现场证据**：数据预取 `prefetchRetailDataForRunPlan`（`retail-data-prefetch.ts`）跑在状态机第 3 站；raw/intermediate/final 三层产物；每份交付带 `sources.json`＋`data_quality.json`；拉取严格按任务合同白名单触发。
- **专业坐标**：medallion 架构（bronze/silver/gold）；provenance（数据溯源）。
- **带走的话**：防幻觉不是靠提示词哀求，是从管道上断粮。

### 原则 3：防腐层要设两道——数据级和代码级

- **一句原则**：外部世界怎么变，核心契约不变；页面代码连自家数据都不盲信。
- **现场证据**：`final` 层是经 13 个 zod 契约校验的稳定形状（数据级防腐）；生成页面用 `asRecord/asArray/numeric` 守卫函数处理一切动态字段（代码级防腐）——字段漂移时页面优雅降级而非白屏。
- **专业坐标**：anti-corruption layer；defensive programming。
- **带走的话**：provider 改版是常态，你的契约是常态中的常态。

### 原则 4：验证必须分层，确定性优先

- **一句原则**：能写死的标准绝不交给概率；便宜的检查先跑，昂贵的裁判只管语义。
- **现场证据**：十项检查分静态六项（翻文件）＋动态四项（真执行）；视觉验收用 Playwright 截图＋DOM 规则判分，**全程无 LLM**；13 个 oracle 断言；评测里 LLM judge 只在语义层且带校准（kappa/MAE）与硬门（grounding/risk < 60 直接挂）。
- **专业坐标**：test pyramid；oracle-based evaluation。
- **带走的话**：凡是"必须对"的事——取数、判分、权限、记账——都不托付给概率。

### 原则 5：不可信代码按敌隔离，权限最小化

- **一句原则**：AI 生成的代码是潜在敌对输入——沙箱执行、最小读取面、专用通道、凭据剥离。
- **现场证据**：动态检查要求 Linux namespace 沙箱，macOS 无此能力即拒跑（fail-closed，逃生门自带警告文案）；页面只许吃 `final`、经营数据只许走平台预取好的 data_file（commerce-data API 只由平台调用，不交给生成页面直连）；审批卡片剥凭据后再给人看；任务信封拒收一切 `key/token/secret` 字段。
- **专业坐标**：sandboxing；least privilege。
- **带走的话**：全链路问一遍"它最少需要碰什么？"——每多给一分权限，都要有理由。

### 原则 6：自治要有界，失败要诚实

- **一句原则**：修复有上限、有作用域、有收敛检测；修不动就把病历写清楚交给人类——而不是伪装成功或无限烧钱。
- **现场证据**：修复上限 3 次（`SHOPGATE_MAX_VALIDATION_REPAIR_ATTEMPTS` 可配）；failure-scoped allowlist（只许动报坏的部位）；失败集合完全相同＝原地踏步，停止无效重试；耗尽 → `failMission` → 未投影（绝不带病交付）。run 1 失败报告指出病根在环境，人类修完环境，run 3 全绿——**失败报告是人机交接文档**。
- **专业坐标**：bounded autonomy；repair convergence；human-in-the-loop。
- **带走的话**：机器修它修得动的；"修不好"本身也是一条有价值的信息，前提是它精确。

### 原则 7：先编排后执行——治理修在必经之路上

- **一句原则**：模型上岗**之前**，车道、预算、工具面就已冻结；模型不拥有任何可"绕过"的位置，因为每个动作都要过闸。
- **现场证据**：`phase-graph.ts` 的 `Object.freeze`（`:55、69`）字面冻结执行车道与预算；standard 车道走 `deterministic-tool-plan`（`:57`）**零模型 Token** 完成标准装配；custom 车道（模型下场）才在 `run-engine.ts` 的三个钩子（`beforeToolCall:1359 / afterToolCall:1501 / shouldStopAfterTurn:1535`）下受治。
- **专业坐标**：plan-and-execute；capability-based security。
- **带走的话**：安全机制的默认值永远朝"多麻烦自己"的方向倾斜——工具没自报危险等级，一律按最危险档处理（`toolset.ts:29`）。

### 原则 8：崩溃恢复三件套＋显式降级

- **一句原则**：多工人、会崩溃、可取消的世界里，靠四件装备维持秩序——心跳租约、fencing 门禁卡、事务 outbox、replan-only checkpoint；依赖残缺时靠**显式降级**跛行而非装死。
- **现场证据**：`prisma/schema.prisma` 五张表同款三件套（`leaseExpiresAt / lastHeartbeatAt / fencingToken`，`:388-390` 等）；`fencingToken only increases`（`:437`）——接手者领更大的号，旧号写入一律拒收，取消＝号数＋1；checkpoint 只存事实不存模型记忆（隐私优先于会话续跑）；受理（job）与通知（事件）同事务；Loki 缺席时黄灯显式标注"已进入降级模式"并附修复指引。
- **专业坐标**：lease & fencing token；transactional outbox；graceful degradation。
- **带走的话**：宿主可以死可以换，账本必须活在数据库里；治理不靠被治理者自觉，靠修在必经之路上的卡口。

### 原则 9：领域知识做成可治理的文档，而不是代码

- **一句原则**：知识是可版本化、可审计的文档资产——改知识≠发版代码；手册管判断，代码管执行。
- **现场证据**：12 个 skill 住在 `.pi/skills/`（SKILL.md 主手册＋references 参考书＋scripts 平台验货脚本＋agents 厂商声明）；`skills.lock.json` 双指纹封存（sourceSha256 源码树＋packageSha256 打包产物）；实验实证：往 SKILL.md 追加一行注释，安检当场咬住——`source hash mismatch … run npm run package:skills`，**报错自带修复指令**；恢复原样即复绿——门咬的是"改动未走流程"，不是"改动"本身。
- **专业坐标**：docs-as-code；content governance；integrity hashing。
- **带走的话**：领域知识的迭代速度与代码发版速度解耦；"商品名→标准商品 id"这类实体解析知识不住在代码里（代码里只有测试夹具），住在 `commerce-entity-resolver` 的 `references/symbol-resolution-contract.md` 里。

### 原则 10：知识分发用规则路由，语义理解才请模型

- **一句原则**：小而结构化的语料用规则路由；向量检索留给大而开放的语料；模型本身就是语义引擎。
- **现场证据**：技能按阶段＋能力目录确定性注入（改写阶段 7 项技能包、生成阶段 dashboard-visualization 单独上岗）；意图匹配先查 capabilities 菜单（每种任务自带示例话术）；**全程零向量**——RAG 会破坏注入的可审计性：写入端指纹可控，读取端却随索引漂移，治理闭环从中间断裂。
- **专业坐标**：routing vs retrieval；RAG 决策信号＝语料规模 × 结构化程度 × 选错代价。
- **带走的话**：RAG 是答案之一，不是默认勋章——先问检索问题有多大、多结构、选错的代价是什么；语料真的大了再上向量，且必配出处（evidence）与检索评测。

### 原则 11：语义翻译分层——查表先行，模型补剩余，解不动就问人

- **一句原则**：能查表的绝不请模型；模型只补语义剩余；fail-closed 的终点是"问人"，不是"猜"。
- **现场证据**："帮我看看这个窗口卖得最好的类目"四层落地：能力目录匹配意图 → 实体解析查表（知识在 commerce-entity-resolver 技能，`rank_candidates.py` 由平台跑——模型没有 shell）→ `query-rewrite` 模型补时间窗与口径 → 模型缺席即暂停（`query-rewrite.ts:770`"大模型未配置，任务已暂停"＝ws-B 那次暂停的产房，`:777` needs_clarification；`:819-821` 还有 partial 档，确定性层已解析的实体不丢弃）。
- **专业坐标**：intent resolution；deterministic-first pipeline；human-in-the-loop fallback。
- **带走的话**：猜错的代价（给错误实体生成一本正经的错误经营诊断）远高于多问一句的成本；已有进展不丢弃。

**阶段 3 取舍卡三张**：①知识为何是文档不是代码——迭代与发版解耦＋审计有据；②lock 为何用指纹不用签名——内部受信源以可追溯为足，拒绝密钥分发复杂度；③规则路由 vs 向量检索——见原则 10 的决策信号。

**工程实践记录（第一次真实代码贡献）**：安检脚本两处裸 `python` 在 macOS 上必挂（本机无此命令）→ 全窝搜捕改 `python3` → 提交 `c9ff7ac`。两条教训：**bug 住在模式里，不住在点上**（修完一个窝立刻 grep 全窝清零）；**"能跑"≠"能验证"**（生成一直好使，但门禁坏了你对改动失明）。

## 四、评测：怎么证明在变好

- **考试与查卷分离**：真跑生成流水线的零售端到端评测（`check-task-e2e-campaign.ts --dataset=task-e2e-retail-v1`，贵，逐 case 生成并验收）与 `eval:ci`（便宜，重算哈希＋验门槛）分离——验证者必须廉价且独立。
- **防作弊五件套**：题库分级（public/hidden/shadow）防押题；prompt-hash 防换题；oracle 断言防"感觉判分"；LLM judge 带校准防放水；receipt/报告哈希防伪造；回归逐题阻断防"改好一处坏三处"。
- **指标语言**：`firstPass`（健康度）与 `repair`（脆性）分开统计；`stability/scoreStdDevMax=0`（确定性车道免费送的可复现性）；`ci95`（对自身不确定性保持诚实）；`durationP95`（用尾部不用平均）。
- **可复现性一句话**：仓库存考纲，不存考卷——你不需要相信历史报告，你只需要相信历史可以被重演。

## 五、迁移到其他项目

- **客服 Agent**：工单生命周期＝状态机；客户数据由系统查好再喂（不信任模型现查）；回复必须引用真实工单号＝evidence；退款等动作走审批闸门；回复质量跑回归评测。
- **自动报告生成器**：与 Shop Gate 几乎同构——数据预取三层＋证据文件＋模板编译＋数字守卫函数；标准场景走确定性车道，语义理解才请模型。
- **代码助手**：沙箱隔离执行；只给必要上下文（最小权限）；生成的补丁先过静态检查再问人；修复建议有界。
- **知识密集型产品（合规问答、内部手册机器人）**：领域知识写成带 lock 的文档资产，规则路由分发；语料大了才上向量检索，且必配出处与检索评测；知识更新走"改文档→重新上锁→过安检"流程，不走发版。
- **通用判断法**：把"生成-验证-修复-评测"四段往任何 LLM 产品上套——四段里有哪段缺失，那段就是将来事故的发生地。

## 六、自己做项目：八问设计顺序

1. **任务有生命周期吗？** → 画状态机：站点、暂停分支、终态语义、落盘位置。
2. **模型吃什么？** → 设计数据通道：谁取数、谁清洗、证据留哪、模型能不能碰外网。
3. **哪些标准能写死？** → 列验证清单，确定性优先排序。
4. **做坏了怎么办？** → 修复上限、作用域、收敛检测、拒收语义，四件缺一不可。
5. **模型能碰什么？** → 权限在它上岗前冻结；卡口修在必经之路上。
6. **怎么证明在变好？** → 考纲先行；判分分层；报告不确定性。
7. **崩了之后呢？** → 快照＋流水双写；租约＋fencing 保证接管合法；从事实重新规划。
8. **领域知识放哪？** → 文档资产＋指纹 lock＋规则路由分发；语料大才考虑向量，且必配出处与评测。

八问的顺序即设计顺序——从 1 到 8，正是本项目板块 A/B/C 推导出的架构链。每问的答案展开，就是毕业设计的一章。
