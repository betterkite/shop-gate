# 后续电商 Agent 能力与数据路线

## 当前结论

当前数据集可以支持四类已经落地的经营分析：流量漏斗、类目结构、价格库存和经营日报。但它还不能覆盖完整的电商经营分析，原因不是 Agent 代码能力不足，而是数据字段本身缺失。

当前可用数据边界：

- 行为数据：2017-11-25 至 2017-12-03 的 `pv`、`fav`、`cart`、`buy` 事件；
- 商品主数据：商品、类目、品牌、店铺、合成价格和合成库存；
- 缺少真实或可追溯的用户画像、会话、来源渠道、活动曝光、优惠券、成本、毛利、退款、履约和长期复购字段；
- 因此当前系统不能直接宣称支持用户留存、RFM、活动归因、利润分析、补货预测或生命周期分析。

后续必须先扩充数据契约，再扩充 Agent 能力和看板。所有新增的合成字段都必须保留 `source`、`synthetic`、生成规则和适用限制，不能把合成分析描述成真实业务事实。

## 金融 Agent 能力到电商能力的迁移矩阵

| 金融 Agent 的成熟能力 | 电商对应能力 | 所需数据 | 不能直接复用的部分 |
| --- | --- | --- | --- |
| 多标的比较、排名、矩阵 | 商品/类目/渠道横向比较 | 商品、类目、渠道、PV、购买、GMV | 不使用证券代码、行情涨跌和金融收益口径 |
| K 线、趋势、量价分析 | 流量、转化、GMV、库存趋势 | 分日行为、库存快照、价格 | 不把 PV/购买曲线解释成价格走势 |
| 基本面与估值 | 成本、毛利、利润和价格带分析 | 成本、售价、折扣、利润 | GMV 不等于利润，不能用 GMV 代替经营利润 |
| 组合风险与集中度 | 库存积压、缺货、商品/类目集中度 | 库存快照、销量、补货周期 | 库销比只是风险提示，不直接生成补货结论 |
| 策略回测 | 促销、价格和库存策略情景评估 | 活动、折扣、历史结果、约束 | 没有实验或历史对照时只能做情景模拟 |
| 公告/事件时间线 | 活动、渠道、节日和商品生命周期 | 活动日历、渠道触点、商品上下架 | 不能把外部资讯逻辑直接当作商品事件 |
| 图片持仓识别 | 运营报表、活动报表和库存截图识别 | 上传图片、字段映射、人工确认 | 识别结果必须区分图片事实和接口事实 |

## 推荐执行顺序

1. `ISSUE-P27`：扩展电商数据契约和可追溯合成数据集；
2. `ISSUE-P28`：补齐用户、利润、活动、库存预测和商品生命周期分析；
3. `ISSUE-P29`：把 6 个领域 Skill 的金融计算脚本改为电商指标脚本，并重发 Skill 包；
4. `ISSUE-P30`：增强 Agent 的多维追问、下钻、行动建议和 BI 看板联动；
5. 每个 issue 都要用新增零售 E2E case、数据质量证据和桌面/移动视觉验收，不以金融 Agent 的页面复刻作为验收标准。

## 范围边界

- 不恢复 `src/lib/domains/finance`、金融 API、证券模板或金融 benchmark；
- 金融 Agent 只作为能力设计参考，不作为电商项目的领域代码依赖；
- 先补数据，再开放对应能力；数据不足时 Agent 必须明确说明“无法判断”的原因。
