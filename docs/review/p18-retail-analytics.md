# ISSUE-P18：零售看板数据分析深度

## 问题定义

P17 已完成页面结构、指标中文化和基础看板层级，但数据分析仍存在三个口径问题：

1. 漏斗只强调事件数，重复行为会让用户误把事件转化率当成用户转化率。
2. 类目结构只有 GMV 排名和集中度，没有把高流量低转化类目单独定位出来。
3. 经营日报的“异动榜”实际按 GMV 总量排序，没有按末日环比绝对值排序，不能准确定位变化最大的类目。

## 实施范围

- `/api/v1/commerce/funnel` 的每个阶段补充 `unique_users` 与 `user_reach_from_pv`，保留事件口径的相对阶段转化率。
- `categories/top` 补充末日相对前一日的 GMV、PV、购买和转化率变化字段。
- 漏斗生成看板展示事件数、独立用户数、事件相对上一阶段、用户触达率，并给出最大事件流失和购买用户触达率。
- 类目生成看板增加高流量低转化诊断表，明确流量阈值和整体转化率基线。
- 日报生成看板按成交总额环比绝对值排序异动类目，并在行动区引用头部异动类目。

## 口径约束

- 事件数允许同一用户重复计数；独立用户数按 `user_id` 去重。
- 用户触达率 = 当前阶段独立用户数 / 页面浏览量（PV）独立用户数。
- 类目异动默认使用窗口末日相对前一日的变化；前一日无数据时不计算，不补零伪造趋势。
- 高流量低转化诊断阈值为类目总 PV 的 5%，且类目转化率低于当前类目整体转化率。
- GMV、价格和库存仍必须标注为合成口径。

## 验收标准

- [ ] 后端 funnel 返回用户去重字段，旧客户端字段保持兼容。
- [ ] 漏斗看板能同时解释事件流失和用户触达率。
- [ ] 类目看板能显示高流量低转化类目；无命中时显示明确空态。
- [ ] 日报异动榜的排序字段和表头明确为成交总额环比，且行动建议引用异动类目。
- [ ] 后端 ruff/pytest、type-check、lint、模板校验、单测、文档/模块检查和 retail e2e 全部通过。
