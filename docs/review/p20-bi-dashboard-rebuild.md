# ISSUE-P20：BI 级电商经营看板重构与运营数据集补足

## 问题定义

当前生成看板虽然能通过基础产物和视觉检查，但 `price-inventory` 只有价格带、库销比 Top 10 和库存健康度三个区域，无法支撑标准电商 BI 的“总览 → 趋势 → 异常 → 拆解 → 行动”分析路径。根因有两层：

1. 最终数据文件只覆盖行为漏斗、类目榜、库存风险和日报快照，缺少跨主题的经营总览、渠道拆解、库存金额和日度经营序列。
2. 视觉验证只确认有图表、表格和来源说明，没有把业务分析闭环作为生成看板的最低合同。

## 数据策略

- 行为事件仍以当前 UserBehavior 事件流为事实来源。
- 价格、库存、渠道、成本、毛利和库存风险等行为流没有提供的字段，使用稳定、可复现的合成投影；所有页面必须显示合成口径。
- 合成投影只用于演示经营分析结构，不得表述为真实订单、真实利润或采购指令。
- 不混入未经对齐窗口和实体的外部电商数据集，避免产生无法审计的多源拼接。

## 目标看板结构

1. 总览：成交总额（GMV）、页面浏览量（PV）、独立访客（UV）、购买、购买转化率、客单价、库存金额。
2. 趋势：分日 PV/UV/购买/GMV/转化率序列。
3. 异常：高流量低转化、滞销库存、低动销、高退货风险代理。
4. 拆解：类目、渠道、价格带和商品明细。
5. 行动：基于数据事实生成补货、转化优化、结构复核和继续观察建议。

## 验收

- `dashboard-data.json` 提供 `biOverview`、`channels` 和扩展后的 `inventoryRisk`，并保留既有零售数据集兼容性。
- 价库看板首屏有 KPI 卡片，首屏或第二屏有日趋势；异常、拆解和行动区均有真实字段绑定。
- PV、UV、GMV 等标签使用中文优先、英文缩写括号补充；合成字段和行为来源显式标注。
- 1440px/390px 视觉检查、模板契约、type-check、单测、后端测试和 `check:retail-e2e` 通过。
- 记录最终数据、来源和视觉验收证据，不将 API key 或原始密钥写入任何产物。
