# ISSUE-P21：BI 数据质量、动销口径与趋势可读性

## 问题

P20 看板的库存健康度直接从库销比风险 Top N 样本计算，而该样本按库销比降序排列，天然会被零销量商品占满；因此“动销占比”可能显示为 0%。同时，零销量商品使用 `0.01` 日均销量地板值，库销比会达到 `500000`，直接绘制原始比值会造成柱状图近似等高。PV、加购和购买还共用同一纵轴，PV 的量级会压扁后两条曲线。

## 处理方案

- 新增 `/api/v1/commerce/inventory-risk` 的全量 `health` 汇总：动销定义为窗口内 `sold > 0`，并独立统计有库存、滞销和无库存商品。
- 合成主数据重建改为与当前行为流对齐并清理旧商品/品牌/店铺/类目，避免切换数据源后旧主数据继续进入库存分母。
- 合成演示商品池默认收敛为 1,000 个 SKU，并按头部 10% / 腰部 30% / 长尾 60% 的流量结构抽样；可通过导入 CLI 的 `--items` 覆盖。
- 预取层和 `biOverview` 透传 `inventory_health`，看板不再用风险 Top N 估计动销占比。
- 库销比明细继续保留原始口径；风险图改用风险样本库存金额，避免库销比地板值主导视觉比例。
- 日趋势按每个指标自身区间绘制趋势线，并在图例中明确这是趋势形状，绝对值仍通过 KPI 和明细数据查看。
- 合成行为增加可复现的周内需求季节性，使 9 日窗口具备可解释的日间波动。
