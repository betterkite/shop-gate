# ISSUE-P30 Agent 多轮下钻与 BI 交互（进行中）

## 本次推进

本次先补齐最容易造成 Agent 误判的商品级证据：商品下钻不再只看订单和库存，还会读取同一 `dataset_id` 下的行为事件，返回页面浏览量（PV）、收藏、加购、购买和购买转化率。这样 Agent 可以回答“商品被浏览了多少、加购了多少、最后购买了多少”，并在下一轮继续沿渠道、价格带、类目或转化问题下钻；同时返回基于当前证据的用户化建议动作。

同时补齐类目维度。`category` 与商品、渠道、活动、用户一样保留数据集隔离，并返回类目级行为漏斗和转化率；数字类目 ID 不被当作商品 ID 解释。

## 验收证据

- 后端单测：commerce-data pytest `42 passed`，其中包含商品下钻行为漏斗字段、无数据安全口径和日趋势筛选验证。
- 真实 API：`retail-demo-p28-elasticity-v1 / item:1000261` 返回 `PV=58`、收藏 `4`、加购 `7`、购买 `5`、购买转化率 `8.62%`，并保留订单、库存和下一步问题。
- 真实 API 同时返回当前数据集、维度和值组成的 `context_url`；前端类型检查通过，工作台下钻表已增加中文字段名、购买转化率百分比和“打开当前下钻视图”链接。浏览器验收确认商品阶段第一页的商品链接能打开该上下文，页面显示商品级行为指标。
- 真实类目 API：`retail-demo-p28-elasticity-v1 / category:10011` 返回 `PV=1,257`、收藏 `109`、加购 `128`、购买 `65`、购买转化率 `5.17%`，并返回类目上下文链接和下一步问题。
- 商品、类目、渠道和用户下钻均返回 `action_suggestions`；页面将其单独展示为“建议动作”，与“下一步可以继续问”分开，避免把问题提示误当成执行结论。
- 浏览器验收确认首页渠道表、商品阶段列表均可点击进入下钻：渠道进入 `dimension=channel`，商品所属类目进入 `dimension=category`，商品本身进入 `dimension=item`，且链接保留当前 `dataset_id`。
- 普通指代型追问（如“这个类目里哪个商品购买转化率最低？”）在没有新实体时会继承上一轮实体、数据集和时间范围；明确指定新商品/类目时不会继承旧实体。新增回归测试覆盖这两种边界。
- 新增日趋势接口并接入工作台：总览展示全店趋势；下钻页按当前商品、类目、渠道或活动刷新趋势；商品/类目保留 PV、购买行为、订单三组真实数量。渠道/活动没有行为事件归因时不再错误复用全店 PV，而是明确显示为 0。
- 浏览器验收确认商品 `item:1000009` 下钻页显示 30 天趋势、PV 合计 `376`、购买 `19`、订单 `19`；“在总览中保留此筛选”可打开 `filter_dimension=item&filter_value=1000009`，页面明确提示其他 KPI 仍为全数据集口径。
