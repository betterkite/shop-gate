# ISSUE-P31 数据集选择与分析联动（第一片）

## 本轮范围

本轮先完成已注册数据集的选择与分析页面联动，不伪造尚未存在的导入事件或异步生成能力：

- `/analytics-workbench` 读取 P27 的 `GET /api/v1/commerce/datasets` 契约列表；
- 页面提供数据集选择器，显示数据集来源、窗口、契约版本、记录数和合成字段；
- 切换数据集通过 `dataset_id` 和当前视图重新请求全部分析接口；
- 页面每 15 秒检查一次 `/api/v1/commerce/datasets`；如果导入 CLI 新增数据集或更新契约时间/行数，自动调用 Next 刷新当前分析；
- BI 工作台提供受控的“生成新的合成经营分析数据集”入口，提交后返回 durable `platform_jobs` 任务 ID，后台生成、质量扫描并可查询进度/失败原因；
- BI 工作台展示最近 8 条数据集任务，区分排队中、进行中、已完成和失败，并显示进度、失败原因或质量扫描完成状态；
- 数据集导入质量扫描通过后自动创建 `analytics_dashboard_generation` 任务，生成 `analytics-bi` 工作台配置清单；任务明确记录数据集、质量扫描证据、视图集合和“尚未生成持久预览”的边界，不把配置清单误报为最终看板预览；
- 数据集区域明确区分“生成合成经营分析数据集”和“导入已有数据集（CSV）”：前者使用确定性合成生成器，后者上传标准行为事件 CSV 并保留真实行为来源，同时为缺失经营字段补齐合成扩展；
- 当前数据集不在契约列表时，自动回退到列表中的第一个已注册数据集，并给出可理解的状态；
- 下钻视图切换数据集时保留维度和值，其他视图不会共享旧数据集的服务端结果；
- 所有请求使用 `cache: no-store`，避免切换后继续展示旧的分析响应。

## 验收

- P27 数据集契约接口已存在并作为唯一数据集来源；
- 页面类型检查通过；
- 文档链接检查通过；
- 页面 ESLint 检查通过；
- commerce-data ruff 与 P31 Python 单测通过；
- 浏览器验收：当前环境已注册 `retail-demo-expanded-v1` 和 `retail-demo-p31-acceptance` 两个数据集；选择器显示默认数据集的窗口、来源、记录数和合成字段，无效 `dataset_id` 已验证会规范化到有效数据集，不会把旧数据继续当作当前数据展示；网页提交的小规模任务成功完成后，新数据集曾出现在选择器中，临时 UI 测试数据已清理。
- 自动刷新通过代码门禁：客户端轮询使用 `cache: no-store`，以 `dataset_id/version/created_at/row_counts` 组成签名，只有发现契约变化时刷新，避免无变化时重复渲染。
- 运行态任务验收：`retail-demo-p31-acceptance`（10 用户、10 商品、3 天）从 `queued` 到 `completed`，质量扫描 `severity=ok`、`issue_count=0`，并返回 7 类扩展表的记录数。
- 任务历史接口验收：`GET /api/v1/commerce/datasets/import?limit=8` 返回已持久化任务；网页导入表单的临时 5 用户/5 商品小任务仅用于快速 smoke，已清理对应数据集，未成为默认分析数据。
- CSV 运行态验收：上传 4 条标准行为事件后任务成功完成，质量扫描 `severity=ok`、`issue_count=0`，结果返回 `behavior_source=userbehavior_csv`；临时 `retail-demo-csv-smoke` 数据集、质量记录和任务已清理。
- 商品级行为验收：CSV 行为明细写入 `dataset_behavior_events` 并按 `dataset_id` 隔离，`GET /api/v1/commerce/analytics/item-behavior` 返回商品级 PV、收藏、加购、购买和购买转化；合成数据集的行为明细同样落入该表并标记 `synthetic=true`。
- 看板编排验收：数据集导入完成后任务历史出现独立“看板配置”任务，状态为已完成，结果带 `template_id=analytics-bi`、7 个工作台视图、质量扫描 ID 和 `preview_ready=false`；这一步只生成可追踪配置，不覆盖用户正在查看的其他数据集。
- Agent 数据集上下文验收：工作台选择的数据集写入浏览器上下文；后续聊天请求携带合法 `datasetId`，写入 run plan，并由扩展分析预取统一传给 `analytics/*` 接口，避免回退到 `retail-demo-expanded-v1`。
- 生成规则验收：合成入口的 `seed` 只用于可复现生成；它会与 `dataset_id`、实体 ID、日期和生成阶段一起派生独立随机序列，分别生成行为、价格、成本、折扣、渠道、订单和库存，不会把 5 这样的验收参数当作系统默认成员数。

## 本轮推进：导入完成后自动切换当前分析

- 合成数据集和标准行为事件 CSV 导入完成并通过质量扫描后，工作台现在会把当前 URL 的 `dataset_id` 替换为新数据集，同时保留当前视图、商品/类目范围、下钻维度和值、项目绑定和日期窗口。
- 页面先显示“正在切换当前分析”，再刷新服务端数据；因此用户不会只看到“已加入选择器”却仍在查看旧数据集，也不会因为自动刷新丢失正在查看的分析上下文。
- 新增 `buildDatasetActivationUrl` 单测，覆盖已有数据集参数和缺失数据集参数两种情况；完整门禁仍需在本片提交前重跑。

跨服务持久化编排已由 `ISSUE-P32` / PR #39 完成：导入任务必须明确绑定 `project_id`，再由事件驱动 Agent 消费配置清单；不能从当前浏览器或最近项目记录中猜测目标项目。P31 尚未覆盖的范围仅包括 CSV 之外的第三方连接器及其独立数据契约。第一片实现与验收记录见 [`p32-analytics-orchestration.md`](p32-analytics-orchestration.md)。
