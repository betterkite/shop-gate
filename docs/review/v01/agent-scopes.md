# R3 经营助手运行归属

本片是持久运行底座，尚未开放新的助手 HTTP 接口、工具或前端。个人和共享数据集的实际授权、范围继承、受控账本查询、多轮、操作确认、取消预算和真实模型仍属于 R3 必须完成的工作；不能用本片数据库测试替代完整助手验收。

## 身份与数据边界

`AgentExecutionScope` 区分旧文件项目和经营数据集。旧项目保留真实 Project 外键；个人经营空间绑定真实 AuthUser，空间标识必须等于该账号的 `account:` 标识；共享空间绑定真实 Project。数据集属于独立经营服务，创建入口必须经过该服务的当前权限与数据集校验，不能假设跨数据库外键存在。

共享数据集中的对话仍私属于发起账号。请求通过复合外键同时绑定对话、执行空间和账号，保存不可修改的原问题、页面范围、数据版本、模型、内容摘要和幂等键。用户会话正文属于私有数据，不作为公开验收附件。数据库约束保证归属一致，但不替代每次请求时的登录、成员、权限和版本复核。

AgentRun 与长期租约使用执行空间作为归属。经营运行从持久请求读取实际账号，不接受调用方另报身份；它的旧 `project_id` 为空，即使是共享数据集也不会被旧项目运行/审批接口选中。运行绑定的模型和规范化执行键必须一致。旧默认恢复扫描仅处理旧项目；经营恢复必须明确指定执行空间并经授权入口处理。

事件、检查点、只读工具证据、版本比较、数据库时钟租约和递增 fencing 继续复用既有运行机制。过期工作进程失去写入资格，不能直接从检查点恢复模型推理。经营运行在存储层拒绝文件工作区写入和物理文件提交；后续工具注册仍须单独限制为受控经营工具。`external_write` 账本记录本身不等于用户批准，正式业务修改仍须预览、明确确认和当前权限复核。

内存仓库只用于旧项目单元测试，不伪造经营账号或会话；经营归属必须通过实际 PostgreSQL 测试。当前尚未提供 BI 账号硬删除流程；清理此类私有数据必须先停止运行并按对话/执行空间的级联关系处理，不能只将发起账号置空。正式账号生命周期行为还需随授权入口集成验收。

## 升级与回退

迁移 `20261107000100_agent_execution_scopes` 在单个事务内建立作用域、会话和请求表，并为原有项目、运行与租约回填归属。既有运行 ID、请求、事件、检查点、workspace key、fencing 计数和旧业务表不被重写。旧调用方省略作用域时，由数据库按其真实 Project 补全并校验。身份不能事后换绑。

正式升级前停止接受新 Agent 运行，等待当前运行结束或明确取消；按[备份恢复说明](backup-recovery.md)备份并验证恢复，再应用迁移和重新生成 Prisma Client。启动时只读 readiness 检查新版列、复合外键、唯一约束及启用的身份保护触发器。旧应用不能与新契约混跑；回退使用已验证的升级前备份，不删除新表来假装无损降级。本文不代表已经迁移日常数据库或生产环境。

## 验证入口

原 `test:backend` 在自建的临时 PostgreSQL 18 集群中执行账本测试，再在独立 Agent 数据库执行所有 Agent PG 测试；不读取日常数据库 DSN。专用 runner 继续运行原 23 项，增加真实个人/共享归属、非法绑定、跨客户端并发、租约接管、证据读取、取消、禁止文件写入和旧库升级测试，任何失败或条件跳过使检查失败。

升级测试在临时唯一 schema 先运行全部旧迁移，写入旧运行、租约、事件和检查点，再应用新迁移。它对全部旧业务表逐行比较内容，并核对运行和租约的新归属、原计数，以及重复 deploy 不产生变化。独立客户端读取证明持久存储可见性，不冒充操作系统重启、完整备份恢复或真实模型验收；这些交付条件仍须另行完成。

## 请求受理与取消（后续候选，完整助手尚未开放）

`src/lib/bi/agent` 将浏览器范围和内部认证分开：外部字段只能包含数据集、版本、明确模型、问题、对话版本和范围；不接受账号、会话、工具或 SQL。内部受理依赖真实登录会话，再以当前 `commerce.data.read` 与 `commerce.operation.run` 校验个人或共享空间。共享对话仍按发起账号私有；查看历史和取消自身分析不要求继续拥有模型执行权限，但必须保有数据访问权限。

范围日期由同版本账本解析一次后保存；金额仍来自原账本。请求和一个 pending 运行在单一事务内写入，以对话锁、版本与内容摘要保证相同请求重试不新增执行，不同内容或过期版本返回冲突。会话引用只保存在私有请求，登出删除会话后保留审计，但 worker 必须拒绝继续。`20261107000200_bi_agent_dispatch` 只增加可空会话引用和取消时间；旧请求没有会话引用不能自动启动。

运行存储新增领取既有 pending 的入口，沿用数据库租约、CAS 和 fencing；已启动或过期运行不能从此入口继续模型回合。待领取的取消直接终态，已领取的取消保存意图，由 worker 检查并停止，不能用本片的取消标记冒充模型调用已中断。测试连接两个真实 PostgreSQL 客户端验证重复并发、身份隔离、撤权、领取与取消，历史每页20条可完整读取。

本片尚未开放请求HTTP/worker/模型工具/页面，也未完成配额预留和独立结算、结果呈现或真实DeepSeek验收；它们仍是下一步必须接通的 R3 闭环。不得因为存储测试通过就让前端提交到无人处理的队列。

用量补计查询已按可空Project处理：`scripts/auth/cleanup.ts`复用只读的`listUnmeteredAgentRuns`，使用NULL安全比较识别已结算的BI运行，保留原事件幂等与金额/来源匹配。专用PG新增旧Project和BI运行的实际配额记录、再次扫描为空以及总量只计一次回归；另新增真实删除会话约束后就绪检查失败且事务回滚恢复的回归。全部专用AgentPG现要求45项实际执行，无跳过；未在日常数据库运行清理脚本。
