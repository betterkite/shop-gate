# R2-A 十二类标准数据交换

对应 [issue #86](https://github.com/betterkite/shop-gate/issues/86)，依赖 #84/#85；当前为开发候选，独立隔离验证结果须另附 revision 和证据。没有执行用户数据库迁移；本片不包括 HTTP 上传、页面或演示数据生成，不代表 v0.1 完成。

## 事实与模板

`ledger/csv_contract.py` 独立定义版本 `1` 的平台、店铺、商品、标准规格、平台映射、汇率、成本、订单、订单行、退款、费用、月目标十二类 CSV。模板列名固定；可选列也须存在，其值可留空。中文字段说明说明必填、允许值与精度。原始平台订单/商品编码保留中文与前导零，内部关联 ID 是稳定文本 ID，不能转为数值。

UTF-8（可带 BOM）、中文、引号、字段换行和空值保真；金额 2 位、数量/单位成本 4 位、汇率 8 位，超精度拒绝，不静默舍入。日期采用自然日期，事件采用带时区 ISO 时间；业务归日仍为北京时间，店铺时区是原始元信息。标准交换文件不加公式前缀以保持往返事实，供系统回导；不应直接执行单元格公式。错误下载另做公式防护且不回显原始单元格。

单文件 20MB，整批 60MB、36 文件、100000 行；每条字段不超过 3000 字符。预览/提交中的单条数据库语句有 60 秒超时；这不是 100000 订单性能已验收，异步大批量流程仍需后续 API/页面与 R7 实测。

`sqls/ledger/008-bi-exchange.sql` 是独立前向迁移，不修改 006/007 checksum。新增市场/模式/时区/展示色/系列、原始平台订单身份、未付款及履约、显式汇率来源、待处理退款空完成时间及未发货取消事实。人民币显式汇率必须为 1；显式原币汇率和来源成对填写。旧 API 内部写入未携带平台号时仅保留旧内部 ID 作为历史兼容值；新 CSV 必须填写真实平台号。

## 预览、确认与完整回滚

`ledger/exchange.py` 在可信空间/数据集/用户/版本下工作，运行角色不能是超级用户或绕过行级隔离。预览按依赖执行实际约束校验和核算，使用回滚保存点，不留下任何订单、成本、快照或版本变化；仅保留私有批次、错误和不可修改的规范化暂存记录，原始上传不进入 Git 或模型上下文。

正式修改必须由有管理权限的原用户明确确认。确认重复核验版本、期限、内容摘要和身份，再在同一事务写入源事实、核算、经营版本、批次、幂等结果及审计。任一后段失败全部回滚；相同提交标识和相同请求可重试，相同标识不得用于其他请求/用户。

同一身份完全相同的记录跳过；同身份不同内容及自然业务键冲突拒绝整批，不覆盖。完全重复导入不增加经营版本或核算快照。元信息/目标新增虽然不改交易金额，仍写入同事实核算版本标记，读查询不会停留在旧版本。

## 核算边界

- 未付款/取消订单和待处理退款保留事实，但不计成交/退款。
- 收入可用订单显式汇率；商品成本独立取付款业务日汇率，不借用订单收入汇率。缺成本/映射/汇率不补 0 或 1。
- 新付款订单行首次生成快照；新增成本/映射/汇率不会隐式修复已有订单行，历史修复仍走单独预览确认重算。
- 新订单可能改变同来源日费用的分摊，预览显示费用影响，确认后追加新版本证据，历史证据保留。源费用始终在全来源范围核算，不能只给当前页面/规格分摊。
- 仅退款保留原成本；可回收退货冲回原付款成本；未发货取消须有原订单未发货状态与取消数量证据，释放对应原付款成本，不当作物理退货。
- 退款时间不得早于付款，累计完成金额/退货及取消数量不得超原行。直接费用归属不得与原行平台/店铺相矛盾。

## 可复核小数据与后续

固定人工样例：USD 原付款金额 20，显式汇率 8，成交 160；2 包每包 2 件，成本 USD 2/件，成本汇率 7，原成本 56。另店付款 100、原成本 10。仅退款 2 USD=16、不回收；退货 1 包退款 5 USD=40，回收成本 28；另一订单未发货取消 0.5 件退款 40，回收成本 5。已知费用 4+6=10。合计成交 260－退款 96－成本净额 33－费用 10＝经营贡献 121。额外未付款/取消订单、待退款不入该金额。期望值来自上述手算，不来自核算函数生成。

真实 PostgreSQL 测试覆盖十二类往返、重复、冲突、后段失败、未知、同键并发、不同预览并发版本冲突、权限/身份/跨数据集、过期、摘要及不可变暂存、重新连接读取批次和全量导出。浏览器、导入页面、正式/演示数据集创建隔离、约 1000 规格/180 天经营演示、性能数据集仍在 R2 后续与 R7，不以本测试替代。
