# R2-B 经营演示生成与导入（局部代码已验，接口页面未完成）

对应 [issue #87](https://github.com/betterkite/shop-gate/issues/87)。`ledger/demo.py` 独立生成虚构经营源事实，没有复制参考数据/实现；不写数据库/文件、不请求外部服务/模型、不注册启动或重置钩子。目录/授权创建、HTTP/长操作和前端仍待接入，不能把生成器当作完整数据集功能。

## 参数和事实

开始日期必须显式提供；种子只决定抽样，不表示日期。默认 180 天、1000 标准规格（两规格对应一个商品，因此500商品）、12000原订单；规模可配置。原订单有已付款/未付款/未成交取消状态，只有已付款进入成交核算。不得将12000原订单写成12000付款订单。

演示提供拼多多、Temu 半托管、1688与9店铺（8经营/1筹备），独立虚构日用清洁、家居、服饰配件、数码配件、运动户外商品名称。SKU/平台原始编码为文本且保留前导零。默认约180天，不依赖种子数字或写死运行日。

整数抽样权重分开表示周内、虚构活动和阶段变化；多数抽样来自热门规格，仍覆盖长尾。价格/采购关系有可解释区间，活动折扣中有亏损样本。报价、成本、退款、费用、汇率都是精确十进制字符串，不以随机图表值替代事实，不宣称真实市场观测。

三层成本、半期基础成本变化、平台包/箱倍数、外币店铺/成本/日汇率/部分订单显式汇率可追溯。退款覆盖仅退款、回收/不回收退货、未发货取消、分次部分退款、待处理，完成事件不早于付款且不超累计原行。商品金额来自订单行实收，而不是浏览购买事件乘价格。

费用记录包括逐行交易费用、店铺日包装/物流/广告及负调整，全部来源标明模拟；比例不是平台真实费率。筹备店无订单仍有广告费用。少量缺成本/映射/汇率故意保留；不能因此用0或默认1伪造。全库完整利润可能未知，页面应展示已核算贡献和覆盖范围，不能虚构全库净利润。

## 可复核来源与限制

返回十二类标准记录及manifest：独立参数、来源/生成器版本、时间范围、行数、内容摘要、场景示例ID、缺汇率日和无销量店铺。manifest是说明，不是核算期望函数。`demo_files` 转为 #86 标准文件，经同一校验/预览/确认服务才能进入账本。

默认事实批次可在标准限额内交换；100000订单是单独性能集，不能因生成参数支持就宣称导入/查询性能通过。超标准批次要有明确分批或受控长作业，不放宽CSV限额。

固定金额仍用 #85/#86 的独立手算验证。新增纯生成测试检查确定性、日期/种子独立、文本、状态、引用、时间/累计退款、成本区间、非平直变化、热门长尾、全部场景和标准CSV；真实PG测试对整套默认规模执行预览/导入/核算，确认不会污染同空间正式集。
