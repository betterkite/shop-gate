# 过期临时文件维护（候选，尚未验收）

对应 [issue #87](https://github.com/betterkite/shop-gate/issues/87)。新增前向011迁移及独立维护命令；不在API/worker启动时运行，不重置数据集，也不自动删除日常用户文件。本候选新增测试尚未运行，不能据文档宣称验收通过。

## 保留内容与回收范围

只回收明确到期的原CSV文件、已生成导出和导入规范暂存行，分别位于`bi.job_files/job_outputs/import_rows`。任务、批次、文件来源摘要、试算、版本、正式经营事实、操作及审计继续保留。原预览仍有效或确认任务正在运行时不回收相关规范行；缺少历史到期时间的对象不猜测日期、不自动删除。

计划每类最多100个任务或批次，显示对象编号、到期时间、条数、字节数和SHA-256计划摘要，不输出文件名、单元格、会话、服务签名或数据库连接。计划5分钟有效，绑定实际维护登录角色。执行必须明确提交同一计划编号和摘要，事务内重新核对；新增、被占用或其他变化导致拒绝并要求重新审阅，不扩大已确认范围。

## 独立权限与并发

011创建两个NOLOGIN/NOSUPER/NOBYPASS角色。运维只将`shopgate_bi_maintenance`授予独立维护登录，不授给普通Web/API/worker。调用组只获两个固定函数执行权，不获经营表或临时文件直接读取/删除权。`shopgate_bi_retention_executor`只作为固定search_path的函数所有者，不得授给任何登录角色或形成成员链；迁移也会拒绝已有危险角色/成员。其跨actor策略仅针对任务临时表，正式经营事实仍按精确范围RLS；它没有正式事实修改权。为与原提交同序取得行锁，执行角色仅有相关头表必要列的锁定权限，函数不修改这些头的来源/版本/预览内容。

维护按数据集→预览→批次→任务顺序取得锁。删除任务文件前还要取得与worker相同的任务advisory锁；即使租约已过期，存活worker持有锁仍阻止回收。到期且租约已失效、实际执行进程已不持锁的遗留任务会明确结束为失败/到期，未提交修改不会恢复；审计回执记录数量。其关联批次若此前被running状态保护，可在结束遗留任务后再审阅下一份计划，不能在原确认后暗加回收对象。

临时表专用触发器仅允许不可登录执行身份的DELETE，UPDATE继续拒绝；普通角色不能通过设置GUC绕过。正式快照、操作和审计的原不可变保护不变。计划与回执也保持不可变。重复确认同一已完成计划返回原回执，不重复删行、不增加经营版本。异常或计数不符时整次事务回滚。

## 运维步骤

先备份并在独立数据库演练恢复，显式安装006–011，不改写已安装迁移的校验和。实际生产/已有数据上的删除须取得对应授权并记录在任务；本轮没有执行此操作。由管理员另建最小维护登录，只授`shopgate_bi_maintenance`。空配置样本为`deploy/bi-maintenance.env.example`，实际连接只放私有系统，不与Web/API/worker或模型凭据混用。

命令只读进程显式的`SHOPGATE_BI_MAINTENANCE_DATABASE_URL`；不发现dotenv，不回退`DATABASE_URL`，拒绝超级用户、绕过RLS或继承执行角色的登录。先运行：

```sh
uv run --project services/commerce-data shopgate-bi-retention plan \
  --workspace-id WORKSPACE --dataset-id DATASET --limit 100
```

审阅计划范围、条数、时间、摘要后，使用输出的编号和完整摘要显式执行：

```sh
uv run --project services/commerce-data shopgate-bi-retention apply \
  --plan-id PLAN_ID --confirm-digest REVIEWED_SHA256
```

计划变化/超时需要重新计划；执行失败不会打印原SQL、连接或原始内容。没有自动定时清理配置。导出下载在保留期到期后，无论物理文件是否已回收，都返回`410/BI_FILE_EXPIRED`，页面提示重新导出；不会返回空CSV或将到期误报无权限。错误校验CSV从保留的安全摘要生成，与原始临时文件分开。
