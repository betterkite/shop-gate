# R3 月度目标维护（候选，待验收）

对应 [#91](https://github.com/betterkite/shop-gate/issues/91) 和功能矩阵OV06/ST03/AG09。目标记录沿用经营账本的店铺与自然月，精确人民币金额；净销售额目标必须非负，经营贡献目标可为负数或未填写。未设定、明确填0、没有经营记录、核算缺失分别保留状态，不伪造完成率。

## 原目标、预览和确认

`ledger/targets.py`先在同一授权只读快照读取店铺、原目标与版本，创建短效私有预览；响应列出原值、新值、是否变化、预计版本及“经营事实不变”说明。不会修改目标、订单、退款、费用或历史快照。预览只允许当前具备管理权限的成员创建，确认只允许原提交人。

用户明确确认后，`confirm_operation`在同数据集锁内重新检查身份作用域、权限、版本、原值、期限、内容哈希及幂等标识。不同预览不能复用同一标识；并发修改/导入使旧预览失效，失败不部分写入。相同确认重试返回原结果；原值与新值相同不增加数据版本。成功修改及无变化确认都有审计，原预览和操作结果可复核。

`recalculation.carry_unchanged_accounting`提取原metadata导入已经使用的同事实版本承接，只能由服务端在已证明事实不变的修改中调用。目标更新增加配置版本和零处理数的核算标记，不生成新订单行成本/费用快照，不重算历史，也不移除Query的版本检查。导入仍先由原核算引擎判断是否需要计算事实，再按原逻辑承接元信息版本。

## 页面与助手边界

`POST /api/bi/targets/preview`和`/confirm`从真实登录、当前管理能力及共享成员角色签发短效管理作用域；只向固定Python同名接口转发受控字段。拒绝跨站请求、自报actor/SQL和任意额外字段，校验返回的空间/数据集/版本。Python再次验证签名、权限及事务条件。基础BI和目标维护不依赖模型。

助手后续只能调用同一预览能力、展示变更及依据；正式确认来自用户独立操作。模型建议、模型输出中的确认标志都不构成用户授权。当前候选尚未接入前端或助手，不能称完整目标维护或OV06/AG09已验收。

总览月目标现在列出全部店铺，包含未设定目标的店铺，按20条分页；总目标仅合计已设定值，并返回已设定数量。净销售与完整经营贡献按所选店铺的完整自然月计算，独立于商品/搜索/部分日期筛选。经营贡献尚未核算完整时不显示误导完成率；部分已核算贡献单独列出。
